# GitCode CLI v0.9.0

v0.9.0 聚焦可自动化交付、安全门禁和本地开发体验，让人类终端、AI 代理与 CI 使用同一套可验证的 GitCode CLI 工作流。

## 新增

- 全局 `--no-interactive` 模式：非交互环境不会隐式等待输入，需要确认时立即给出可操作错误。
- 21 个命令新增当前仓库自动识别能力，覆盖更多 Issue、PR、Release、Commit、Label 和 Milestone 场景。
- 项目级开发环境检查与安装脚本，支持只读检查、主机工具安装和结果汇总。
- GitCode 原生 Actions CI 流水线，与 GitHub 镜像 CI 共同提供 Linux 和跨平台验证。
- Issue 支持按 milestone 编号过滤。

## 改进与修复

- Issue 创建和编辑按用户名提交负责人，并增加真实读写系统回归。
- `pr edit` 保留未指定标签，PR JSON 输出补全最终状态并统一空集合表示。
- Milestone 详情按实际 Issue 数据计算数量，避免依赖缺失的接口字段。
- 修复 Web 登录入口、登录模式冲突和 GitCode 域名限制。
- pre-commit/pre-push 门禁覆盖格式、私钥、敏感信息、工作区和 Git 历史扫描。
- 系统测试增强临时资源命名、分页清理和残留可观测性。
- 版本 JSON 输出正确传播写入错误，并统一 API 错误解码。
- 移除仓库内已废弃的共享 skills，独立 skills 仓库继续作为安装来源。

## 验证

- Windows 与 WSL2 Linux amd64：全量 Go UT、integration、race、vet 和 golangci-lint。
- WSL2 Linux：以 `infra-test/gctest1` 为唯一对象执行真实只读和写入 system 测试。
- WSL2 本地打包：Linux amd64/arm64、DEB、RPM、wheel 与 sdist 均构建成功。
- 全新 Linux venv：`gitcode`、`gc`、`python -m gc_cli` 三个入口均验证通过。
- pre-commit、pre-push 与 gitleaks 工作区/历史扫描通过。

## 安全

- AI 和自动化不得读取、打印或通过命令行参数传递真实 token。
- 内容写入命令继续执行敏感信息扫描。
- 本地验证制品不用于正式发布；正式制品由合入后 main 的 release workflow 构建并携带准确 commit SHA。
- 正式发布将构建与 tag/Release/PyPI 写权限分离，并提供覆盖归档、裸二进制、DEB、RPM、wheel 与 sdist 的 SHA-256 清单。

## 已知限制

- GitCode 官方 OpenAPI 当前没有 Release 删除接口；`release delete --dry-run` 可用于预览，实际删除请使用仓库 Release 页面。

## 安装

### Wheel（推荐，跨平台）

```bash
pip install https://gitcode.com/gitcode-cli/cli/releases/download/v0.9.0/gitcode_cli-0.9.0-py3-none-any.whl
gitcode version
```

### Windows 安装后配置

虚拟环境中请先在 PowerShell 运行：

```powershell
.\.venv\Scripts\Activate.ps1
```

未使用虚拟环境时，直接安装 GitCode Release 中的 wheel，避免 PyPI 尚未同步新版本时安装到旧版本：

```powershell
py -m pip install --user --upgrade https://gitcode.com/gitcode-cli/cli/releases/download/v0.9.0/gitcode_cli-0.9.0-py3-none-any.whl
$scripts = py -c "import os, sysconfig; print(sysconfig.get_path('scripts', os.name + '_user'))"
$env:Path = "$scripts;$env:Path"
gitcode version
```

确认后，将 `$scripts` 对应目录持久加入 Windows“用户环境变量”的 `Path` 并重新打开 PowerShell。配置前可直接运行：

```powershell
py -m gc_cli version
```

PowerShell 已将 `gc` 用作 `Get-Content` 的别名，因此 Windows 推荐使用 `gitcode`、`gc.exe` 或 `py -m gc_cli`。
